## CNN-17 이후 실험 방식 변경
지금까진 기본적인 튜닝만 진행. 막히지는 않고 아직 뭔가 해볼 수 있는 기본 튜닝 또는 추가 기법이 있긴한데
그 전에 해보고 싶은 것을이 있다.

- 그리드 탐색 횟수 계산 -> 후보값 개수가 정해져야 실제 횟수 계산 가능
- 랜덤 서치 -> 탐색 범위가 먼저 필요
- K-Fold 교차검증 -> 이것도 할려고 헀는데, 찾아보니 CNN은 학습 비용이 너무 커서 범위가 없으면 오래 걸린다 (그냥 돌릴까 하는데 그건 좀)

### 그럼 17 이후에는 무엇을?
= 먼저 탐색 범위를 설정하자. 

1. 탐색할 하이퍼파라미터 선정
2. 각 파라미터의 탐색 범위 설정
3. Grid Search 총 실험 횟수 계산
4. 너무 많으면 Random Search로 축소
5. 좋은 후보 1~3개만 K-Fold로 재검증
6. 마지막에 Test Set 평가

그럼 줄바꿈 줄이고 **한 줄에 여러 정보를 붙이는 식**으로 가면 돼.

## CNN-20은 WRS를 쓰자
### Weighted Random Search for CNN Hyperparameter Optimization 논문 참고

NN-19까지 직접 범위를 줄여가며 탐색했으니, CNN-20부터는 WRS(Weighted Random Search)를 적용해보기
논문에서는 일반 Random Search에 확률적인 Greedy 방식을 섞어서, 모든 하이퍼파라미터를 똑같이 랜덤으로 바꾸지 않고 중요한 파라미터는 더 자주 바꾸고 덜 중요한 파라미터는 현재 좋은 값을 유지하는 방식으로 탐색.
같은 수의 조합을 실험했을 때 얼마나 좋은 정확도를 찾는지를 기준으로 다른 최적화 방법들과 비교하기

CNN-20에서는 CNN-19 결과를 기준으로 범위를 다시 좁혀보기

Learning Rate: 0.0003 / 0.0004 / 0.0005 / 0.0007 / 0.001
Dense: 128 / 192 / 256
L2: 0.00001 / 0.00005 / 0.0001 / 0.0003 / 0.0005

Epoch는 최대 100, Early Stopping은 그대로 유지

처음 몇 번은 일반 Random Search로 조합을 뽑고 결과를 모은 뒤, 그 결과를 기준으로 각 하이퍼파라미터의 중요도를 계산
이후에는 중요도가 높은 값은 더 자주 변경, 중요도가 낮은 값은 현재까지 가장 좋은 조합의 값을 유지하면서 탐색
대충 흐름은
Random Search로 초기 결과 수집 → 하이퍼파라미터 중요도 계산 → WRS 적용 → 좋은 조합 쪽으로 탐색
전체 Grid Search는 5 × 3 × 5 = 75개지만 전부 돌리지 않고, CNN-20에서는 총 20회 정도만 탐색하기
